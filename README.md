# To-Do 리스트

## 소개

같은 요구사항 문서(PRD)를 두 가지 CSS 프레임워크로 구현한 일일 할 일 관리 앱입니다. 할 일을 추가·삭제·완료하고, 전체·진행 중·완료 필터로 목록을 확인할 수 있습니다. 입력과 목록은 브라우저의 `localStorage`에 저장되며 새로고침 후에도 유지됩니다.

## 어떻게 만들었나요

1. `PRD.md`에 목표, 상태, 예외 처리, 저장 방식, 화면 구성과 완료 기준을 작성했습니다.
2. 누락된 필터·삭제·손상된 저장 데이터·모바일 동작 기준을 추가해 PRD를 보완했습니다.
3. 완성된 PRD를 기준 커밋으로 만든 뒤, `bootstrap`과 `tailwind` 브랜치에서 각각 구현했습니다.
4. 두 버전의 완료 기준 충족 여부와 화면을 비교하고 Tailwind 버전을 선택해 `dev`에 통합했습니다.
5. 최종본을 다듬고 README와 배포 설정을 완성했습니다.

## Bootstrap vs Tailwind

| 비교 항목 | Bootstrap | Tailwind |
|---|---|---|
| PRD 완료 기준 | 10개 모두 충족 가능 | 10개 모두 충족 가능 |
| 빈 입력·긴 문장·HTML 입력 | 통과 | 통과 |
| 모바일 화면 | 반응형 컴포넌트와 유틸리티로 구성 | 유틸리티 조합과 폭 제약이 일관되게 적용 |
| 디자인 완성도 | 전통적인 컴포넌트형이고 안정적 | 정보가 조밀하고 장식과 레이아웃을 세밀하게 조정 가능 |
| `index.html`의 class | `container`, `btn`, `nav-pills`, `form-control` 등 의미 있는 완성 부품 클래스 | `flex`, `grid`, `px-4`, `rounded-md` 등 작은 스타일 조각의 조합 |

최종 선택은 Tailwind입니다. 두 버전의 기능 충족 수준은 같지만, 선택 후 커스터마이징과 모바일 폭 조절을 유틸리티 조합으로 직접 관리하기 쉬웠습니다. 특히 필터를 테이블 형태의 밑줄 탭으로 바꾸고, 본문 폭이 작은 화면에서도 입력창과 추가 버튼이 가로로 겹치지 않도록 구성했습니다.

## 커스터마이징한 부분

- 필터를 전체·진행 중·완료 세 구역의 밑줄 탭으로 구성했습니다.
- Tailwind 유틸리티와 소량의 CSS로 산뜻한 종이 질감과 인디고 강조색을 적용했습니다.
- 모바일에서 패널 그림자와 여백을 줄여 화면 폭을 효율적으로 사용합니다.
- 할 일 항목 텍스트는 `overflow-wrap: anywhere`로 설정해 긴 문장과 공백 없는 문자열이 카드 밖으로 넘치지 않게 했습니다.
- 사용자가 입력한 텍스트는 `textContent`로 출력해 HTML 태그가 실행되지 않고 문자 그대로 보이도록 했습니다.
- 마감일과 높음·보통·낮음 우선순위를 항목에 표시하고, 기한이 지난 미완료 항목은 별도로 강조했습니다.
